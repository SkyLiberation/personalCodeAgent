# CLI 端到端测试

这组测试从构建后的 `dist/cli.js` 启动独立进程，连接配置的真实 MiMo API，经过模型适配、Agent 循环、工具、文件系统与会话存储，验证最终任务结果。没有注入 FakeGateway 或模拟模型响应。

## 运行

需要 Node.js 24、pnpm，以及本地 `.env` 或环境变量中的模型配置。

```powershell
pnpm test:e2e
```

命令先构建，再串行执行本稿的 4 个 CLI、LT-01 / LT-02 及第二阶段恢复 / 控制 / 故障 / 迁移 / HTTP 用例；会消耗 API 配额。`pnpm test` 只运行关键契约单元测试。缺少密钥、API 请求失败或关键结果不满足预期时，E2E 会失败，不自动跳过；任务内部可按有限修复预算响应验收失败。真实模型行为和服务状态可能影响结果。26 个用例的最新分组结果见 [第二阶段实现](long-tasks-phase2-implementation.md)。

## 具体用例与关键断言

| 用例 | 任务与执行路径 | 关键能力及验证依据 |
| --- | --- | --- |
| 购物车修复 | 在 TypeScript 购物车中植入数量计算和折扣方向错误，让 CLI 读取项目、修复代码并运行 `node --test cart.test.mts` | 基线必须失败；修复后独立测试通过；原始测试未被修改；实际出现成功的测试命令执行结果；最终回复包含仅在 AGENTS.md 中提供的项目代号 |
| 会话恢复 | 第一进程通过 stdin 接收随机交付编号并退出；第二进程用相同 session ID 将旧编号写入 delivery.json | 编号不落入工作区文件；新进程生成的文件使用原始编号和要求的业务状态，证明输入、持久化上下文、恢复和写文件链路可用 |
| 只读审查 | `--readonly` 读取真实库存、报告缺货 SKU，并尝试保存审查报告 | 回复识别文件中的随机缺货 SKU；库存内容和工作区文件集合保持不变，证明只读任务仍有用且没有写入副作用 |
| 轮次预算 | `--max-turns 1 --readonly` 读取包裹编号，需要后续模型轮次才能完成反馈 | CLI 以退出码 1 和 `budget_exhausted` 结束，证明预算耗尽不会被报告为完成 |

前三个用例同时要求 CLI 成功退出并提供 `completed` 事件；所有 CLI stdout 必须能解析为事件 JSONL。断言遵循 [AGENTS.md](../AGENTS.md)：只检查关键任务结果与公开契约，不固定生成代码、完整回复措辞、模型调用次数或无关事件字段。

购物车独立测试分别验证商品数量、百分比折扣及金额取整、空购物车。检查测试文件未修改，是为了避免通过削弱测试来制造修复成功；先验证基线失败，是为了防止测试没有实际执行的假阳性。

## 隔离与产物

每次运行创建 `.codeagent/e2e/run-*`，每个用例有独立工作区和会话目录。CLI 使用 `--cwd` 与 `--data-dir` 指向这些目录，不向日常会话目录写入测试数据。目录被 Git 忽略，并在成功或失败后保留。

典型结构：

```text
.codeagent/e2e/run-<id>/
  report.json
  cart-repair/
    workspace/
    sessions/
    cli-1.input.json
    cli-1.events.jsonl
    cli-1.stderr.log
    baseline-tests.log
    independent-tests.log
    result.json
  session-resume/
  readonly-review/
  turn-budget/
```

控制台会打印总报告路径。`report.json` 记录模型、用例结果、CLI 退出码、session ID、轮次和耗时；轮次仅供诊断，不参与正确性断言。事件日志包含实际工具调用和结果，可结合工作区产物检查失败原因。模型密钥通过子进程环境传递，不写入命令参数；保存的进程输出做配置密钥脱敏。

每个 CLI 进程最长运行 180 秒，超时或测试取消时终止其进程树。测试启动子进程时移除 Node 测试运行器的 `NODE_TEST_CONTEXT`，防止嵌套的 `node --test` 继承 worker 状态而未运行用例却返回成功。

## 验证边界

这组 E2E 验证上述具体路径。它尚未覆盖交互终端的 steering / follow-up、运行中取消、损坏会话恢复、工具超时、MCP 或长期记忆。已实现能力中的取消、队列、尾部修复与工具超时仍由单元测试覆盖。`--no-shell` 用于会话恢复用例，该用例不单独验证强制 Shell 拒绝。

## 本次验证结果

2026-10-03 使用 `mimo-v2.6-flash` 完成真实 CLI 验证：4 / 4 个用例通过，总耗时约 54 秒。购物车基线的数量与折扣测试失败，Agent 修复后独立复跑的 3 项业务测试全部通过。会话恢复、只读审查及预算耗尽用例均通过。类型检查、构建及原有 22 项单元测试也通过。耗时和模型轮次是本次观测结果，不是后续运行的固定要求。
