# docs 维护规范

本目录继承 [工程规范](../AGENTS.md)。文档维护必须同步反映源码和真实验证结果。

- `e2e/` 保存用例和验收。每例必须包含具体任务、步骤、实际检查、证明范围，并引用设计及其合理性；设计反向引用对应用例。
- `pending/README.md` 是当前未完成事项的唯一清单。功能待办和验证待办分开，写清缺口、验收规格及迁出条件；不把历史 planned 复制成新待办。
- `implemented/` 保存已实现的设计、源码、使用方式和实际报告。能力部分完成时明确剩余待办链接，不用“全部完成”覆盖尚缺的子能力。
- 原阶段设计及报告放在相应的 `history/`，保留当时的失败、跳过和范围，显著链接当前状态。
- 待办通过其完成门槛后，必须在同一次更新中移至已落地区、从清单删除、清理旧文件和状态，并修复 E2E 与设计的双向引用；不能只勾选完成后长期留在待办目录。
- 实现已有但验收未通过或未执行时，剩余验证仍留在待办；没有真实模型结果不能宣称模型相关能力已经验收。未注册的 E2E 规格不计入当前用例数。
- 更换文档位置后运行递归链接和锚点检查；新增或移动用例说明时核对测试注册名和设计引用。纯文档整理不要求重新消耗模型配额，但须说明引用的是既有记录。

流程与索引见 [docs/README](README.md)。
