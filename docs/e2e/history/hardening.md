## 实际任务与验收

| 用例 | 初始环境与真实路径 | 故障与关键验收 |
| --- | --- | --- |
| HT-01 成功提交前文件变化 | SDK + 真实 MiMo 实现 value()=42，独立进程验收通过 | 在最终证据核查后、成功提交前把文件改为 -1；必须 blocked 且没有最终成功引用。独立验收实际失败；宿主恢复文件后显式 resume，重验通过，不再请求模型 |
| HT-02 写入目标缺失 | 真实模型通过 write 实现接口；工具完成、结果未提交时终止执行进程 | 宿主删除目标文件，另一进程 resume；必须 effect_unknown / blocked，不增加实际模型请求或工具启动。恢复原内容后同任务 resume 成功，原写操作不重放 |
| HT-03 回执查询不可用 | 真实模型调用非幂等登记工具；副作用完成、结果未提交时终止进程 | 宿主暂移回执，查询抛出实际 ENOENT；必须保持可恢复阻塞，不新增模型请求或审计登记。恢复回执后完成独立验收，审计标记始终只有一次 |

测试入口为 tests/e2e/task-hardening.test.ts，公开 SDK 与独立工作进程使用真实 PiModelGateway。请求审计只记录进程 / 时间，不记录提示或密钥；故障屏障只控制真实执行时机。保存状态、事件、独立验收输出与 report.json。

HT-01 的成功含义绑定提交前最后一次核查的合同、源码与产物指纹；工作区执行权只互斥协作执行者。它不保证其他主机进程在最终核查之后不能再改文件，任务成功不承诺工作区永远不变。

## 既有证据补强

- LT-04 未知效果：直接观测真实模型请求与工具启动，不仅比较 Run 计数。
- LT-04 输入交接：保留原计划 input ID / run ID / 内容摘要，只接收一次。
- LT-04 孤立附件：恢复后的最终引用不得采用孤立附件，并实际执行新的验收。
- 订单合同：错误、缺失 CSV 表头必须被独立验收检查。
- 迁移：验证旧文件保留与孤立代际未被采用，移除固定目录数量断言。
