# 已实现扩展能力的 E2E 规格

2026-10-05。本页保留已实现扩展能力的任务与验收规格。实际结果见 [实现记录](../implemented/current.md)，设计选择及每个用例的双向引用见 [设计证据索引](../implemented/design-evidence.md)。历史检索与快照新增实际任务见 [专门用例](history-snapshot.md)；平台与规模也有独立验收，不能由本页结果代替。

## 先定义实际任务

| 编号 | 初始环境、输入与真实入口 | 产物与关键验收 |
| --- | --- | --- |
| LT-11 | 六模块事件 JSONL 归档查询工程，各模块留下错误；SDK + 真实模型按宿主合同实施 | 宿主随机数据检查解析行号、UTC、最新 revision 去重、聚合、范围与 CLI；记录全部尝试 |
| LT-12 | 工程可在模型工具批次完成后通过验收，启用 verification 完成策略 | 全批次结果提交后门禁通过即可让出；同批次登记不能遗漏，未完成阶段不能成功；默认 natural 不变 |
| LT-03 | 在真实工程会话加入早期随机标签与大段诊断，触发摘要；中断摘要提交、重新打开 | 原始事实保留，投影缩小、标签由实际摘要保留、完整工具组不拆开；已提交摘要重用，孤立摘要无效；必需上下文超限明确阻塞 |
| LT-06 | 宿主在真实执行后反复恢复相同缺陷，另一次在重规划后停止破坏 | 有限 replan 后 no_progress；新验收能力通过才清零，正向变体完成 |
| IN-01/02 | 公开 SDK 接受 follow_up/steer，在 accepted/consumed 后退出，再打开同会话 | 稳定 inputId 回执、内容冲突拒绝、消费消息与事实原子提交；未消费可恢复，已消费不重复注入 |
| RT-01/02 | 显式 429/503/连接错误的单次网关尝试，之后真实模型完成工程；持续失败 | 每次尝试进入统一账本，重试次数/等待时间持久受限；参数/业务错误与未知效果不重试 |
| LX-05 | 真实 Linux 组日志绑定 bootId/PID namespace，替换来源标识 | 恢复拒绝且无误杀；旧日志不猜测来源；正常恢复依旧有效 |
| BG-01 | 真实子进程运行有界等待，退出或超时，宿主重启 | 进程身份、完成回执与等待日志持久，恢复只核查不重启未知命令 |
| BD-01 | 小累计 token/时间/费用额度，摘要/重试共享，恢复后继续；分别增加请求数、执行次数额度 | 持久预留及未知用量保守计入；只增加请求数不能绕过 maxRuns；增加对应额度才可继续，重复命令幂等、版本 CAS、历史用量不清零；所有额度耗尽后仍可复验宿主修复；费用须提供明确价格 |
| GD-01 | 用户自然语言目标和宿主验收器目录，模型草拟阶段；明确确认后创建任务 | 草稿不执行，合同只引用宿主验收器，确认 hash 防旧稿；任意工程需可信门禁才可成功 |
| WF-01 | 两个独立工程节点和一个依赖合并节点，SDK 调度 | DAG 检测环、并发有限、依赖验收成功才放行；单节点失败/取消阻止下游，独立会话和工作区 lease 不绕过 |
| EX-01 | 嵌套 AGENTS、声明 skills、显式受信任扩展含 register/dispose | 来源/hash 可查，路径指令按范围，技能按需读取，未授权可执行扩展不能自动加载，重复工具拒绝，关闭释放资源 |
| MCP-01 | 本地真实 JSON-RPC 工具服务器，列工具并调用，连接断开/取消 | 公开 SDK 包装工具完整往返，输入 schema 验证，副作用默认 never，协议错误不冒充成功 |
| MCP-02 | 真实 stdio 服务故意不响应、发送坏协议或退出；公开 client 请求 | 超时/取消有通知并拒绝，断连/坏协议拒绝而非成功；错误输入不能调用服务 |
| MEM-01 | 两次独立 SDK 会话，第一写显式记忆、第二检索，分支在完整工具组后建立 | 记忆仅宿主授权内容、不自动保存秘密；分支有来源 cursor，原会话不变、不克隆未结算工具效果 |
| RPC-01 | 真正子进程的 JSONL RPC，submit/steer/abort/status/close，慢订阅者 | CLI 与 SDK 共用会话，稳定请求 ID、错误回执；展示有界缓冲，不能阻塞事实提交 |
| ENV-01 | 容器执行适配器使用宿主显式镜像与挂载清单运行真实命令 | 只挂载工作区、网络默认关闭、超时/取消删除容器；没有可用 Docker 明确 unavailable，不能降级为有主机权限的 shell |
| PAR-01 | 同批两个声明 parallelSafe 的独立 read，随后写和进程工具 | 并发上限、调用顺序持久提交，副作用串行，全批次结束后才验收 |

## 参考与取舍

沿用 [优化方案](../implemented/optimization.md) 固定的 pi、DeepSeek Harness、Hermes 提交。采纳 append-only 投影、完整工具组边界、持久 inbox 和质量门禁；扩展由宿主显式授权，MCP 只承载工具协议；工作流留在 Harness，运行时保持单 Agent。后台等待不承诺未确认副作用的 exactly-once。容器适配不把目录白名单称为 OS 沙箱。

各项已实现，源码/使用入口/实际通过与失败以及环境限制见 [完整落地记录](../implemented/current.md)，每个注册用例的步骤与证明范围见 [新增详解](advanced.md)。不能删除旧限制文字来代替实现，也不能把模拟响应当作真实模型验收。

联合工程标签验收增加隔离条件：Agent 的 shell 只能访问容器工作区，不挂载宿主请求日志、事实文件或早期诊断归档；标签还必须实际出现在已提交摘要中。否则即使最终标签正确，也可能来自读取宿主日志，不能证明摘要保留了早期信息。此变体需 Linux Docker，业务门禁继续由宿主执行。
