## 共用实际工程：事件归档与查询 CLI

使用 TypeScript / Node 内置模块完成一个事件处理工程。工作区提供有缺陷的解析、规范化、去重、聚合、查询和 CLI 实现；这些模块形成真实依赖链，阶段由宿主预定义，不把通过结果扩大为自主阶段规划能力。

用户任务：读取 JSONL 事件，把不同时区时间规范化为 UTC，按 eventId 去重（保留最新修订），按项目 / 日期 / 严重级别聚合，支持时间范围查询，从真实 CLI 生成归档与报告。非法记录必须带行号诊断，不能输出成功报告。

输入至少包括：重复 ID、乱序修订、跨日时区、中文、空输入、非法时间、非法严重级别和损坏 JSON。验收器使用宿主持有的固定 seed 派生多个未写入工作区的输入变体，独立计算期望值，防止实现只返回示例结果。不要求特定私有函数、内部调用次数或代码行数。

阶段：解析与诊断 → 时间与数据规范化 → 修订去重 → 聚合 → 查询 → 实际 CLI 交付。产物为真实归档、聚合报告与查询 JSON。最终从新进程运行 CLI，检查各模块之间的契约和错误出口，并保护原始输入及验收文件。

基础用例 LT-11 在未启用新控制能力时完成一次完整交付，作为上下文 / 预算 / 停滞用例的共同基线。报告记录实际模型请求、完整回复、工具效果、验收、新旧进程和最终产物；运行耗时不能单独作为复杂长任务证据。

## LT-03：请求上下文受控缩减后完成实际工程

初始用户输入带随机 runLabel 和业务约束；runLabel 不写入工作区提示文件。宿主通过公开 SDK 追加来自真实诊断文件的材料，并设置可承载必要内容的较低软阈值，确定触发缩减。不能访问私有队列或伪造 assistant 的 providerData。

关键验收：

- 请求前确实生成并使用了较小的上下文投影；原始持久历史完整保留。观测投影事件和实际请求，不能只看摘要声明。
- 保留区间中的 assistant 原生协议数据完整；工具调用与结果成组保留，无孤立结果。已经缩减的前缀不重新进入后续请求。
- 最终真实 CLI 报告带正确 runLabel，规范化 / 去重 / 聚合 / 查询与非法输入均通过独立验收。
- 跨进程恢复后采用已提交的有效摘要及保留边界，仍能完成剩余阶段；摘要提交前中断不能采用孤立摘要。
- 必要目标、当前工具组与输出预留已超过硬容量时，明确 context_capacity_exceeded，不静默删除约束。

runLabel 若被当前合同每轮重新注入，只能证明合同投影保留目标，不能单独证明模型摘要保留了早期信息。报告必须说明实际采用的保留路径，两者分别观测。

## LT-05：跨进程累计模型请求预算

先以全局模型请求次数作为最小预算契约，不同时引入成本定价、任意预算维度和新的存储系统。任务使用小额度，在多个阶段 / 上下文缩减之间显式暂停恢复。

关键验收：真实模型分派次数不超过上限；正常执行、摘要和重规划请求使用同一账本。额度在分派前提交，进程退出或 usage 缺失不退还已预留次数。恢复与需求更新不得清零。耗尽后不能启动新请求；任务停止后的新工具副作用也不能启动。已经准入的模型轮次及完整工具批次如何结算，应在实施前明确约定并验证。

另一个变体在请求已分派但 usage 未返回时终止进程，恢复检查该请求仍占额度、usage 为未知；不能靠日志缺失把用量当零。断言请求数量是公开预算契约，不固定业务任务应恰好需要多少次请求。

## LT-06：没有有效进展时有限继续

在去重阶段每次真实模型执行后、验收前，宿主持续恢复同一个业务缺陷。真实验收因此重复失败；文件被编辑不能冒充进展。

设置小的无进展窗口和一次策略调整机会，要求在额度内停止为 blocked: no_progress，保留重复失败、已验证能力及已尝试修复的证据。不把模型输出“换了策略”的文字当成重规划已有效。

正向变体在策略调整后停止覆盖，让真实模型落实修复并通过后续聚合、查询和 CLI，验证有效验收进展会解除停滞判断。缺失且禁止编造的外部输入另列 blocked 用例，不能替代停滞检测证明。

## 交付与范围控制

每项重要能力都必须从公开 SDK / CLI 执行，模型相关路径使用真实 MiMo，独立程序检查实际产物；确定性的协议与提交排列由单元 / 进程集成测试补充。报告保留 failed / not_run，区分同次套件通过、分组通过与多次运行成功率。

在这些用例成立前，不扩展 DAG、多 Agent、后台服务或旧格式兼容层。累计 token / 时间 / 费用预算、任意项目自主规划和跨平台恢复继续单独标为未实现。
